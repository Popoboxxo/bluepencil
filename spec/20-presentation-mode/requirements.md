Three states, and off is not a variant of read: off leaves the layer and the host page untouched; read shows the presenter panel without a write path; edit shows the same panel with the two write paths. One gesture toggles off and read. An audience tab is read-only by construction and never gets a write path. Teardown removes the panel, the timer and the channel, and is idempotent (FR-12.2, NFR-15)

*Acceptance criteria:* With the mode `off` no panel, timer or channel exists; toggling opens the panel in `read` and closes it again; an audience tab has no write path; `destroy()` and `disable()` leave no panel, timer, listener or channel behind and can be repeated

One store, no second truth: the mode reads the note set from the layer's own store, so a speaker note is the same note the review list and the export show; a write from the panel goes through the layer's normal mutation path, and a store change refreshes the panel. An agent can create or update such a note over MCP or the hub without knowing about presentation mode

*Acceptance criteria:* A note created over MCP appears in the presenter panel after a refresh; a body edit in `edit` mode is visible in the list and in the export; the panel never holds a note set of its own

The panel states the plan and the position: the clock reads elapsed / planned; the cue list is in talk order, grouped by chapter, and marks the cue that is due now with aria-current. The pure timing functions are the contract: readCues orders timed notes by at (ties by createdAt) and appends untimed notes last, using anchor.route or the host's route provider as the chapter; totalDuration sums the cues' own durations (missing duration counts as 0); currentCue returns the last cue with at at or before the elapsed time, and nothing before the first cue

*Acceptance criteria:* `readCues` returns timed notes ascending with untimed notes last and the route attached; `totalDuration` is the sum of durations and `0` when none is set; `currentCue` is `undefined` at elapsed 0 before the first cue, returns the cue exactly at its start, returns the last cue behind the end, and never returns an untimed note

## FR-20.4 A cue is optional note data, not a second model: a note may carry timing {at, duration?,…


A cue is optional note data, not a second model: a note may carry timing {at, duration?, label?} in seconds; at must be finite and non-negative, duration and label are optional. The canonical form emits the cue at a fixed key position and omits optional keys that carry no value; timing: null clears the cue, an omitted timing leaves it untouched, and corrupt timing is dropped on read rather than resurrected. Markdown exports a cue as m:ss, or h:mm:ss once the talk runs past an hour

*Acceptance criteria:* A note without `timing` stays valid and is not migrated; `timing: null` clears an existing cue and an omitted field preserves it; a non-finite or negative `at` is dropped; the canonical bundle places the cue at the fixed position; the Markdown export renders `m:ss` below one hour and `h:mm:ss` above it

Edit mode writes through the same path and the clock is explicit: edit exposes the note text and the cue, both persisted through the layer's mutation path; one control starts and pauses the clock, another resets it to zero; the clock marks an overrun when the elapsed time passes the planned duration. The audience view is a second same-origin tab, read-only, with no server: it is addressed by ?bp-present=1 (with bp-mode=read), talks to the presenter tab over a BroadcastChannel, and makes no network request of its own (FR-9.4, NFR-7). It reflects the presenter's elapsed time and mode; a blocked popup is reported instead of failing silently; without BroadcastChannel the audience tab still shows the page and the presenter tab still works

*Acceptance criteria:* Opening the audience view produces a same-origin URL carrying `bp-present=1` and `bp-mode=read`; the tab has no write path and performs no fetch; the presenter's elapsed time reaches it over the channel; a refused popup is reported; without `BroadcastChannel` no exception is thrown and the presenter keeps working

Chapter stepping belongs to the host: the layer knows its notes, not the talk. Stepping to the previous or next chapter asks the host through the same route provider that names a note's chapter; the layer never guesses a chapter order of its own

*Acceptance criteria:* A step calls the host's chapter handler with `+1` or `-1`; without a host handler the key does nothing and throws nothing; the layer never computes a chapter list from the note set

A collision-free keyboard profile: every presentation shortcut is a Shift combination (Shift+P toggle, Shift+E read/edit, Shift+O audience, Shift+Space start/pause, Shift+R reset, Shift+←/Shift+→ chapter), so the host's unshifted navigation keys (j/k, 0–9, s, t) stay with the host. Esc leaves the mode like it closes the other layer surfaces, and the legend lists the effective keys

*Acceptance criteria:* Each presentation action is reachable only with `Shift` held; the unshifted host keys still reach the host while the mode is active; `Esc` leaves the mode; the legend lists the presentation group and follows a remap
