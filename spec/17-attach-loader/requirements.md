One tag attaches with the documented defaults: a <script src="attach.js"> with no data-* attribute at all defines the element and, with data-auto at its default true, mounts exactly one <bluepencil-notes> on document.body; data-auto="false" defines the element and mounts nothing. window.bluepencilAttach exposes version, src, instances, destroy(), reload() and check(), plus handles and attach(options) for the per-script and programmatic view

*Acceptance criteria:* A page with one bare loader script ends with exactly one mounted element and a populated `window.bluepencilAttach`; `data-auto="false"` yields zero mounted elements but a defined tag; a tag added after `DOMContentLoaded` is picked up by `check()`; `destroy()` removes every mounted element and the layer

One attribute vocabulary for element and loader: every element attribute has a data-* mirror on the loader, and only non-empty loader values are forwarded (so data-voice without a value is not forwarded). The same module decides attribute names, defaults and the attribute-to-configuration rules for both the custom element and the loader. A global path (gate, headers-from, route-from, can-annotate, annotate-selectors, keymap, modes, dock) that cannot be resolved or parsed is reported, never silently ignored

*Acceptance criteria:* Every documented element attribute is accepted in its `data-*` form with the same meaning; an empty `data-*` value is not forwarded as an empty attribute; an unresolvable global path produces an `element.issues` entry (element) or a `bp-attach-error` plus one `console.debug` line (loader) instead of a silent no-op

Runtime update without a page reload: with data-manifest the loader reads the pointer {version, element, sha256}, compares the version by equality (never by order) and swaps the layer when it differs; data-watch polls at the configured seconds (0 = off), reload() and check() do it on demand. bp-attach-ready, bp-attach-updated and bp-attach-error report the outcome on document. The loader never throws into the host page: every failure becomes bp-attach-error plus one console.debug line

*Acceptance criteria:* A changed manifest version tears down the old layer and mounts the new one without a reload and emits `bp-attach-updated` with `from`/`to`; an unchanged version swaps nothing and `reload()` resolves with `0`; a malformed manifest produces `bp-attach-error`, leaves the previous layer in place and does not throw; `destroy()` removes the element, the layer and the watch timer

Optional integrity check of the element build: with data-integrity="true" the loader verifies the manifest's sha256 against the fetched element file with WebCrypto before executing it. The digest is a download check, not an execution guarantee; a host that needs assurance pins the build itself

*Acceptance criteria:* With `data-integrity="true"` and a matching digest the build loads; a mismatching digest, an unreachable file or a missing WebCrypto implementation is reported through `bp-attach-error` and never presented as a successful check; with the attribute absent the loader does not fetch a digest
