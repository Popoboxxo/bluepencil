Every accepted mutation is recorded: create, update, message, bulk-delete and import produce an entry with operation, note ID (when there is one), actor (when known), summary, sequence number and timestamp. --journal auto (the default) chooses git when the store lives inside a git work tree and file otherwise; --journal none disables history on purpose. A requested backend that cannot be provided degrades to none with a reported reason, never silently

*Acceptance criteria:* Each of the five operations yields one entry with `op`, `noteId` (where applicable), `actor` (where known), `summary`, `seq` and `ts`; `auto` selects `git` inside a work tree and `file` outside one; `--journal git` outside a work tree reports `none` plus a reason on `stderr` and in the status instead of doing nothing

Auditable, replayable history: the file backend is append-only and hash-chained (each entry hashes the previous one), so tampering is detectable; GET {base}/journal returns {journal: {backend, location, entries, lastSeq}, entries} and accepts ?since=<seq> to return only newer entries, oldest first. The journal route is GET-only and answers 405 to OPTIONS

*Acceptance criteria:* The file backend writes one line per mutation with `prevHash`/`hash`; a modified line breaks verification; `?since=1` does not repeat entry 1; the response carries the status object and the entries; `OPTIONS` on the journal route answers `405`

Journal failures never roll back a note, and the git backend is path-limited: the note is persisted before the journal is written; a failure is reported once on stderr and stays visible in the status and in GET {base}/journal. The git backend stages and commits only the configured store and mirror paths, coalesces mutations over --journal-coalesce ms (default 2000) into one commit, and takes its identity from --journal-author or BLUEPENCIL_JOURNAL_AUTHOR (flag wins). The public journal keeps location and author; that is the accepted risk documented in FR-6.7

*Acceptance criteria:* A failing journal runner still lets the note write succeed and reports the failure once; two mutations inside the window produce one commit that touches only the configured paths; a pre-staged foreign change stays out of the notes commit; `journal.author` reports the configured identity, or the repository identity when none is configured
