# CQ-03 `createLayer`-Split (Epic-Plan, Contract L)

> **Status:** `draft` — Epic-Plan zu **T-L1** (Spec §3.13 L, AC-L01, ADR-0.12-S7).
> **Quelle (normativ):** `docs/specs/0.12.0-audit-remediation-spec.md` §3.13 L.
> **Einordnung:** L ist kein Bestandteil der Welle A–K; es ist der letzte Knoten der
> Merge-Reihenfolge (§3.12) und läuft nach dem Doku-Tail (T-T1).
> **Leitplanke:** **kein Verhaltenswechsel**, keine neue öffentliche API, `LayerHandle` und die
> `createLayer(options)`-Signatur bleiben unverändert, keine neue Runtime-Dependency.

## 1. Ziel und Zuschnitt

`src/ui/layer.ts` ist mit ~2.200 Zeilen die größte Datei der Bibliothek und trägt fünf
Verantwortlichkeiten in einem Closure. Der Epic zerlegt sie in **vier** kohesive Einheiten mit
expliziten Abhängigkeiten und je eigenem `dispose()`; die fünfte Einheit (`dispatchTool`-Tabelle)
gehört zu **T-L2** und wird hier nur als Folge-PR geführt (Spec §3.13 L, AC-L02).

Nicht Teil des Epics: Marker-Geometrie (`renderMarkers`/`positionMarkers`), Host-Event-Routing
(`onDocumentClick`/`onDocumentChange`/`onDocumentKeyDown`), Container-Aufbau (`buildRoot`) und
Export (`exportNotes`) bleiben im Composition Root `layer.ts`. Sie sind entweder reine
DOM-Fabrikation oder das Dispatch-Netz, das genau eine Stelle haben soll.

## 2. Modul-Landkarte

| Modul (neu) | Einheit | Öffentliche Form |
|---|---|---|
| `src/ui/layer-unit.ts` | gemeinsamer Dispose-Vertrag | `interface LayerUnit { dispose(): void }` |
| `src/ui/layer-presentation.ts` | **Presentation** (FR-20) | `createLayerPresentation(deps): LayerPresentationUnit` |
| `src/ui/layer-notes.ts` | **Note-Mutationen** (FR-2.3/5.5/8.1) | `createLayerNotes(deps): LayerNotesUnit` |
| `src/ui/layer-jump.ts` | **Highlight/Jump** (FR-4.7) | `createLayerJump(deps): LayerJumpUnit` |
| `src/ui/layer-settings.ts` | **Settings** (FR-4.5/4.10/12.9/12.12/12.13) | `createLayerSettings(deps): LayerSettingsUnit` |
| `src/ui/layer-teardown.ts` | **Teardown** (FR-12.2/NFR-15) | `createLayerTeardown(): LayerTeardown` (`add(dispose)`, `run(onError)`) |
| `src/ui/layer.ts` | Composition Root | `createLayer`, `LayerOptions`, `LayerHandle`, `ChromeLevel` (unverändert) |

**Abhängigkeitsrichtung (strikt azyklisch):**

```
layer.ts ──▶ layer-presentation.ts ──▶ present.ts
         ──▶ layer-notes.ts        ──▶ core/{store,anchor,capture,protocol,model}, panel.ts, composer.ts
         ──▶ layer-jump.ts         ──▶ core/anchor, panel.ts
         ──▶ layer-settings.ts     ──▶ panel.ts (Typen), i18n, modes.ts
         ──▶ layer-teardown.ts     ──▶ layer-unit.ts
         ──▶ layer-unit.ts
```

Kein Einheiten-Modul importiert `layer.ts` (kein Zyklus). Einheiten kennen einander nicht; jede
Abhängigkeit auf eine andere Einheit wird vom Root als Callback übergeben (`panel: () => Panel | null`,
`renderAll: () => void`, `mutate` …). Damit ist jede Einheit ohne den Root testbar.

## 3. `dispose()`-Vertrag je Einheit

Grundregel: `dispose()` ist **idempotent** und gibt **nur** Ressourcen frei, die die Einheit selbst
erzeugt hat. Fehler werden über den übergebenen `onError`-Kanal gemeldet, nie geworfen (NFR-14).

| Einheit | Eigene Ressource | `dispose()` gibt frei | Beobachtbarer Beleg |
|---|---|---|---|
| Presentation | `PresentationHandle` inkl. 250-ms-Ticker + `BroadcastChannel` | `destroy()` des Handles, Referenz auf `null` | `ui.test.ts` Teardown (kein Timer/Channel), `present.test.ts` |
| Note-Mutationen | `activeTarget` (Composer-Ziel) | Ziel verwerfen; keine Listener | `ui.test.ts` „disable clears target“ / Composer-Reopen |
| Highlight/Jump | `highlight`-Knoten + `animationend`-Listener, `selectedId` | Listener entfernen, Knoten-Referenz + Auswahl verwerfen | `layer-jump.test.ts` (Listener weg, `selectedId === null`) |
| Settings | `settings`-Objekt, Translator, `chromeOverride`, `narrow` | Referenzen verwerfen; **persistiertes** Setting bleibt (FR-4.5) | `layer-settings.test.ts` (Persistenz über `dispose()` hinweg) |
| Teardown-Registry | geordnete Liste von `dispose()`-Schritten | führt alle Schritte in **Registrier-Reihenfolge** aus (ein Fehler stoppt die Liste nicht) | `ui.test.ts` NFR-15-Zyklustest |

**Reihenfolge in `disable()`** (exakt wie heute, nur als Liste):
`listeners` → `store`-Subscription → `resizeObserver` → Oberflächen schließen
(panel/composer/legend/settings) → Presentation → Highlight/Jump → Note-Mutationen →
State-Reset (Marker, Resolutions, Degradations, Modus) → Styles freigeben → Root entfernen.
Der Root registriert die Einträge in genau dieser Reihenfolge (`registerTeardown()`), `run()`
arbeitet die Liste vorwärts ab. Ein `dispose()`-Fehler stoppt die Liste **nicht**; er geht an den
`onError`-Kanal (NFR-14). Die Settings-Einheit schließt die Liste ab — ihr `dispose()` gibt nichts
frei, weil die gespeicherte Präferenz `disable()`/`enable()` überleben muss (FR-4.5).

## 4. Gestapelte PR-Reihenfolge

Jeder PR ist ein eigener Branch (`feat/0.12-l<n>-<name>`, Basis = Vorgänger-PR) und wird erst
gemerged, wenn `npm test` **und** `npm run smoke:embed` grün sind. Kein PR ändert DOM-Ausgabe,
Event-Verdrahtung, Styles, Timing oder Accessibility.

| PR | Einheit | Inhalt | Gate |
|---|---|---|---|
| **PR-L1** | Presentation | `layer-presentation.ts` + `layer-unit.ts`; `createPresentation`-Verdrahtung, `present.*`-Shortcuts und `refresh` wandern hinein | `npm test`, `npm run smoke:embed`, `npm run size` |
| **PR-L2** | Note-Mutationen | `layer-notes.ts`; `mutate`, `authorName`, `saveNote`, `replyTo`, `panelActions`, `confirmDelete`, `noteForNode`, `captureSafely`, `activeTarget` | dito + `npm run typecheck` |
| **PR-L3** | Highlight/Jump | `layer-jump.ts`; `jumpTo`, `showHighlight`, `moveSelection`, `jumpToIndex`, Highlight-Knoten + Listener, `selectedId` | dito |
| **PR-L4** | Settings/Teardown | `layer-settings.ts` + `layer-teardown.ts`; Settings-State/Persistenz/Chrome/Narrow, geordnete Dispose-Liste in `enable()`/`disable()` | dito + `npm run build` |
| **PR-L5** | `dispatchTool`-Tabelle | **T-L2, nicht T-L1**: `src/mcp/tools.ts` `name → handler`, AC-L02 | `npm test` |

**Nach jedem PR:** `npm test`, `npm run typecheck`, `npm run build`, `npm run size`,
`npm run smoke:embed`. Zusätzlich je Einheit eine fokussierte Testdatei, wo die Naht sauber ist
(`tests/unit/layer-presentation.test.ts`, `layer-notes.test.ts`, `layer-jump.test.ts`,
`layer-settings.test.ts`); die DOM-Ebene in `tests/unit/ui.test.ts` wird **nicht** abgeschwächt.

## 5. Rollback je Stufe

Der Epic ist rein strukturell; jede Stufe ist einzeln rückrollbar:

| Stufe | Rollback | Wirkung |
|---|---|---|
| PR-L1 | PR revertieren | `layer.ts` enthält die Presentation-Verdrahtung wieder; übrige Stufen unberührt |
| PR-L2 | PR revertieren | Note-Mutationen zurück im Root; PR-L1 bleibt |
| PR-L3 | PR revertieren | Jump/Highlight zurück im Root; `selectedId` wieder Root-State |
| PR-L4 | PR revertieren | Settings/Teardown zurück im Root; Dispose-Liste entfällt, alte `disable()`-Reihenfolge kehrt zurück |

Ein Rollback ist **vollständig** (kein halber Zustand): jede Stufe fügt ihre Module neu hinzu und
entfernt den entsprechenden Block aus `layer.ts` in genau einem Commit. Ist eine Stufe nicht in
einem kleinen, sicheren Schnitt grün zu bekommen, wird sie revertiert und als *deferred* mit
Begründung gemeldet — der Baum bleibt nie rot.

## 6. Risiken und Gegenmaßnahmen

| Risiko | Gegenmaßnahme |
|---|---|
| Reihenfolge-Effekte im Teardown (NFR-15) | Dispose-Liste reproduziert die heutige Reihenfolge; `ui.test.ts`-Zyklustest ist das Gate |
| Zyklische Importe Root ↔ Einheit | Einheiten importieren nur `core/*`, `i18n`, `ui/{panel,composer,present,modes}` und `layer-unit.ts` |
| Bundle-Budget (IIFE/Element ~97 % belegt) | Extraktion ist Verschiebung, kein Feature; `npm run size` nach jedem PR, Grenze bleibt unverändert |
| Verhaltensdrift durch „Aufräumen“ | Keine Umbenennung von Verhalten, keine geänderten Callback-Reihenfolgen; Diff-Review je PR |
| `LayerHandle`-Fläche | Unverändert; `tests/unit/ui.test.ts` prüft die Fläche weiterhin |

## 7. Abnahmekriterien

- AC-L01: fünf PRs benannt, je eigenes `dispose()`, `npm test` + `smoke:embed` nach jeder
  Extraktion grün, kein Verhaltenswechsel, `LayerHandle` unverändert.
- AC-L02 (T-L2): `dispatchTool`-Tabelle ersetzt den 10-Case-`switch`, gleicher Fehlercode.
- `tests/unit/ui.test.ts` bleibt ohne Abschwächung grün (2210+ Tests im Repo-Stand).
